FIELD NOTES / ISOLATED TRAINING LAB

Blackpearl
Follow the boundaries.

This investigation concerns an intentionally vulnerable, isolated training VM. The account identities below are lab identities. Public notes omit passwords, hashes, callback addresses, and unrelated local data.

A vulnerable CMS provided the initial foothold. A privileged PHP interpreter turned that foothold into root access. The useful lesson was in connecting two separate trust failures: remote application execution and unnecessary local privilege.

01 / Find the application behind the default page

The report records hostname discovery and a local mapping for the lab’s virtual host, followed by HTTP verification. Directory fuzzing initially returned many identical HTTP 200 responses: 652 bytes, 82 words, and 27 lines. A status code alone was not enough to distinguish content.

Filtering the repeated 652-byte response reduced the noise. A distinct /secret result appeared, and a later enumeration pass discovered /navigate. The report identifies Navigate CMS 2.8 there. The secret directory was an enumeration result, not the established initial-access vector.

02 / Establish the foothold

The notes describe using the Navigate CMS RCE module and obtaining command execution as www-data. The successful module invocation was not retained in full; the report identifies some configuration commands as reconstructed. I preserve that distinction instead of presenting a reconstructed session as terminal history.

03 / Inspect local privilege

Basic sudo and history checks did not produce a useful path. Broader enumeration with LinPEAS led to PHP 7.3 and its privileged execution configuration. An interpreter with elevated effective privileges is particularly dangerous because it can start other processes.

The saved report transcribes the successful invocation of PHP’s pcntl_exec() to start /bin/sh with privilege preservation. The subsequent identity check returned:

whoami
root

This confirms the reported root identity. It does not establish a complete real/effective UID listing; the sample id output in the source report is explanatory, not captured evidence.

04 / Break the chain

  • Upgrade or replace the vulnerable CMS and reduce its exposed functionality.
  • Keep application service accounts narrowly privileged.
  • Remove unnecessary SUID permissions from interpreter binaries and audit privileged executable ownership.
  • Retest both remote application execution and local privilege boundaries after remediation.

Evidence and limitations

Based on the original Blackpearl report and retained lab notes. The report records a www-data foothold and a successful root identity check. Exact DNS command output and the complete successful CMS exploit invocation were not preserved. No remediation retest is claimed.
