Replay how sast-triage handles one pull request containing all ten examples: label each finding new or pre-existing, rank it P1–P3, then decide whether the check fails.

P1: high or critical severity in runtime code. P2: high or critical in test code, or medium in runtime code. P3: everything else. A rule rated low confidence drops one level. The check fails only on new P1 findings; everything else is annotated.

Illustrative triage. File paths, severities and new or pre-existing labels are invented for this walkthrough; the ranking and gate rules match the real tool’s analyzers/triage.py. The real reviewer triages Semgrep findings only, so the six behavioral examples would not appear in a real check.
