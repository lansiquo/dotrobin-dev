PROJECT

sast-triage

I built sast-triage, a GitHub pull request reviewer that scans the changed Python, JavaScript and TypeScript files with Semgrep, labels each finding new or pre-existing, ranks it P1–P3 and fails the check only on new P1 findings.

The problem

A Semgrep step in a repository’s own CI flags every finding, including ones the pull request didn’t introduce, and the pull request can edit that step. sast-triage runs outside the repository with its own rules and separates what a change introduced from what was already there.

Nine findings cover five of NodeGoat’s lessons. It misses the rest: log injection, plain-text passwords, insecure direct object references, missing security headers, plain HTTP, missing access control, CSRF, server-side request forgery and a ReDoS-prone regex. No rule covers those, HTML templates aren’t scanned, and data isn’t traced across files. Vulnerable dependencies (A9) are sca-triage’s job.

How it works

The service verifies each pull request webhook’s HMAC-SHA256 signature, downloads the head commit, and scans only the changed Python, JavaScript and TypeScript files with its own 29 Semgrep rules (15 Python, 14 JavaScript and TypeScript). Repository configuration and nosemgrep comments can’t switch them off, and Semgrep never downloads rules: it accepts only the service’s own rule file. Results go back as Check Run annotations, P1 first. scan_repo.py runs the same rules, triage and gate on a whole repository.

Ranking combines severity with where the code lives:

  • P1: high or critical, in runtime code.
  • P2: high or critical in test code, or medium in runtime code.
  • P3: everything else.

A finding is new when it overlaps a line the pull request added or changed, and only a new P1 fails the check. An unreadable diff makes every finding new, and scanner errors or incomplete scans fail the check, so a problem can over-report but never pass silently. Unsafe archive entries such as path traversal and links are rejected before anything is written.

Built with Python, FastAPI and Semgrep as a GitHub App. Source: labelling, ranking and the gate · scanner checks · rules · architecture.

Scope and limits

  • Covers Python, JavaScript and TypeScript with 29 pattern rules. They match within one file, so a value passed through another function or module before a dangerous call isn’t traced.
  • HTML templates aren’t scanned. Pair it with sca-triage for npm dependencies and with other tools for secrets and infrastructure.

Run it yourself

Use Python 3.11–3.14. These are the commands from steps 01 and 02:

git clone https://github.com/lansiquo/sast-triage.git
cd sast-triage
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
make check
git clone https://github.com/OWASP/NodeGoat.git ../NodeGoat
git -C ../NodeGoat checkout c5cb68a
.venv/bin/python scan_repo.py ../NodeGoat

Run scan_repo.py on any project folder; add --json for machine-readable output. It exits with 1 when the gate fails, 0 when it passes and 2 on an error. To review pull requests, register your own GitHub App, as the README describes.
