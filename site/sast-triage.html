sast-triage

I built sast-triage, a GitHub pull request reviewer that scans the changed Python files with Semgrep, labels each finding new or pre-existing, ranks it P1–P3 and fails the check only on new P1 findings.

The problem

A Semgrep step in a repository’s own CI flags every finding, including ones the pull request didn’t introduce, and the pull request can edit that step. sast-triage runs outside the repository with its own rules and separates what a change introduced from what was already there.

Severity sets the level, test code lowers it, and whether the pull request touched the line decides if it can fail the check. MD5 is as serious as shell=True, but this pull request didn’t change that line, so it’s reported without blocking.

How it works

The service verifies each pull request webhook’s HMAC-SHA256 signature, downloads the head commit, and scans only the changed Python files with its own 15 Semgrep rules; repository configuration and nosemgrep comments can’t switch them off. Results go back as Check Run annotations, P1 first.

Ranking combines severity with where the code lives:

  • P1: high or critical, in runtime code.
  • P2: high or critical in test code, or medium in runtime code.
  • P3: everything else.

A finding is new when it overlaps a line the pull request added or changed, and only a new P1 fails the check. An unreadable diff makes every finding new, and scanner errors or incomplete scans fail the check, so a problem can over-report but never pass silently. Unsafe archive entries such as path traversal and links are rejected before anything is written.

Built with Python, FastAPI and Semgrep as a GitHub App. Source: labelling, ranking and the gate · scanner checks.

Scope and limits

  • Covers Python with 15 pattern rules: weak hashes, unsafe YAML and pickle loading, shell commands, eval/exec, disabled TLS verification, insecure randomness and temp files, and unsafe tar extraction. They match patterns, not data flow.
  • Pair it with sca-triage for npm dependencies and with other tools for secrets, JavaScript and infrastructure.
  • Findings are review aids; rules can miss issues or report false positives.
  • To use it on your own repository, register your own GitHub App, as the README describes.

Run it yourself

Use Python 3.11–3.14. The demo environment has known dependency advisories, so use it with the bundled fixtures only. These are the commands from step 01:

git clone https://github.com/lansiquo/sast-triage.git
cd sast-triage
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
make check

make check runs the tests and the demo shown in steps 01–04.

For the interactive version, run .venv/bin/python demo_web.py and open http://127.0.0.1:8765. Four examples run real Semgrep scans; six run behavioral tests on hash-pinned fixtures against synthetic adapters. The pull request view is simulated.
