# Portfolio contribution guidance

## Lab writeups

- Call these pages **Writeups**, not penetration-testing reports, pentesting reports, or formal assessments. Update the page title, heading, description and cards consistently when adding a page. Formal reports are separate deliverables.
- Use `class="content article writeup"` and `writeups.css` for every lab writeup. Preserve the dark portfolio design, favicon, navigation and unrelated project content.
- Keep every writeup on the same layout: a `reading-layout` with the `reading-toc` "On this page" sidebar and a `class="environment"` target list. Each lab writeup uses exactly eight `<h2>` headings, in this order and unnumbered: Overview, Reconnaissance, Initial access, Privilege escalation, Result, Attack path, Remediation, Key takeaways. No step-titled headings; step details are content under these headings. The attack path sits in the red `attack-path` panel (numbered chain) and remediation in the blue `defense-panel`, each finding paired with its fix (`finding-pair`: Finding and Fix), both styled by `writeups.css`. Match this structure when adding a page.
- Wrap every screenshot in `<figure class="evidence">` (styled frame and caption) with an inner `.evidence-scroll` region. Never use a bare `<figure>`, which `writeups.css` does not style. The figure may hold either a scrollable `<img>` or an `<a>` linking the full-size capture.
- Use high-contrast semantic `<pre><code>` panels for actual commands/output, with `tabindex="0"`, an accessible label, horizontal overflow and readable monospace text. Mark inline commands, account identities and paths with `<code>`.
- Write in confident first person about what Robin did and found: short, plain sentences with no hedges, evidence caveats or disclaimers. Never invent commands, outputs, results, screenshots, client work, or remediation that was performed. Take new facts only from Robin's own commands, tool output and terminal screenshots (his lab notes); assistant commentary in the notes is not evidence.
- Prefer genuine matching screenshots from authorized lab notes. Inspect original pixels before selecting, crop irrelevant application chrome, remove metadata, and redact secrets or unrelated private content before publication. Do not generate synthetic terminal screenshots. Preserve originals unchanged.
- Keep only deliberately selected evidence files under `site/evidence/`. Never publish a whole vault, raw credential dumps, tokens, cookies or unrelated files. The owner explicitly authorized public disclosure of ordinary identifiers from these isolated offline labs on October 30, 2026. Preserve authentic lab usernames, hostnames, paths and system details in the selected evidence. IP addresses stay placeholders (`<TARGET_IP>`, `<CALLBACK_IP>`). Continue excluding actual passwords, tokens, cookies, private keys and unrelated personal data. Strip metadata. Keep source originals and private review galleries outside the repository. Do not fabricate missing values or evidence.
- Use responsive `<figure>`/`<img>` with intrinsic dimensions, meaningful alt text and a factual caption. Link to the original-size published image for legibility. Avoid duplicate captures. Keep command text selectable when available.
- If a step's output was not captured, describe the step without a caveat and without fabricated output, or drop the sub-detail; do not claim expected output was captured. Consult `EVIDENCE.md` for current coverage.
- Validate balanced HTML, internal assets/links, screenshot dimensions, absence of sensitive incidental data, command preservation and scope. Verify the exact deployed commit and live HTTPS bytes after publishing. State when rendered browser QA was not performed.
- Never change DNS, HTTPS settings, account permissions or hosting providers as part of a content/style edit.
